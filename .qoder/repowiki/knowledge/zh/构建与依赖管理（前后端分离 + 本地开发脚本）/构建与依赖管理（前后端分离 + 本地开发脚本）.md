本仓库采用前后端分离架构，未使用统一的 Makefile、Dockerfile 或 CI 流水线，而是通过各自生态的标准工具进行构建与依赖管理：后端 Python/FastAPI 使用 pip + requirements.txt，前端 React/Vite 使用 npm + package.json，并通过根目录的 Windows 批处理脚本一键启动开发环境。

### 1. 后端构建与依赖
- 依赖声明：backend/requirements.txt 锁定 FastAPI、Uvicorn、SQLAlchemy(async)、Alembic、Celery、Redis、MinIO、Qdrant、OpenAI、Pydantic 等全部运行时依赖；backend/requirements-core.txt 是精简版（移除 opencv-python-headless、Pillow、aiohttp），用于更小的镜像或轻量部署场景。
- 数据库迁移：使用 Alembic，配置文件 backend/alembic.ini 指向 MySQL（asyncmy 驱动），迁移脚本位于 backend/alembic/versions/。
- 配置注入：通过 python-dotenv + pydantic-settings 加载 backend/.env，包含数据库 URL、Redis、MinIO、LLM API Key、Qdrant 地址等。
- 进程模型：Web 服务由 Uvicorn 启动（uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload），异步任务由 Celery Worker 执行（见 backend/app/tasks/celery_app.py）。

### 2. 前端构建与依赖
- 依赖声明：frontend/package.json 定义 React 18、Ant Design、React Router、TanStack Query、Vite 6、TypeScript 5.6 等依赖及 devDependencies。
- 构建流程：npm run build 先执行 tsc -b 做类型检查，再调用 vite build 生成静态产物到 frontend/dist/。
- 开发代理：frontend/vite.config.ts 将 /api 请求反向代理到 http://localhost:8000，解决开发期跨域问题。

### 3. 本地开发入口
- 一键启动脚本：start_dev.bat 依次完成：
  1) pip install -r backend/requirements.txt
  2) 后台启动 Uvicorn（端口 8000，带 --reload）
  3) npm install
  4) 后台启动 Vite Dev Server（端口 5173）
- 脚本同时输出后端、前端和 Swagger 文档地址，便于开发者快速验证。

### 4. 版本与发布约定
- 版本号集中在 frontend/package.json 的 version 字段（当前 0.1.0），后端无统一版本文件。
- 未发现 Dockerfile、docker-compose.yml、Jenkinsfile、GitHub Actions 等 CI/CD 配置，生产打包与部署流程尚未在仓库中落地。

### 开发者应遵循的规则
- 新增后端依赖时同步更新 requirements.txt 与 requirements-core.txt，保持两者差异最小化。
- 修改数据库模型后，使用 Alembic 生成并审查迁移脚本，不要手动改表结构。
- 前端新增页面或组件需确保 TypeScript 编译通过（npm run build 会触发 tsc -b）。
- 环境变量统一写入 .env（后端）或通过 Vite 代理访问后端，避免硬编码 URL。
- 如需容器化或 CI，建议补充 Dockerfile 与 GitHub Actions/GitLab CI 配置，以补齐当前缺失的自动化环节。
